3.What is hoisting in JavaScript?

Hoisting is JavaScript’s behavior of moving variable and function declarations to the top of their scope before execution.

var is hoisted but initialized with undefined.

let and const are hoisted but kept in Temporal Dead Zone (TDZ).

Functions are fully hoisted.

9.What is the difference between function declaration and function expression?

A Function Declaration is hoisted and can be called before it’s defined,
while a Function Expression is not hoisted and can only be called after it’s assigned.

🧠 Function Declaration
// ✅ Works before declaration due to hoisting
console.log(add(2, 3)); // 5

function add(a, b) {
  return a + b;
}


✅ Hoisted — The entire function is hoisted to the top of its scope.
So, you can call it before its definition.

⚙️ Function Expression
// ❌ ReferenceError
console.log(add(2, 3));

const add = function(a, b) {
  return a + b;
};


❌ Not hoisted — Only the variable add is hoisted, not its value (the function).
So calling it before definition causes an error.

17.How do you implement Debouncing and Throttling in JavaScript? Give examples.

Debouncing means making sure a function runs only after a certain delay — and only if the user stops performing 
the action during that time.
It helps to reduce unnecessary function calls, like when typing in a search box or clicking a button repeatedly.

Example
// Debounce function
function debounce(fn, delay) {
  let timer;
  return function(...args) {
    clearTimeout(timer); // reset timer
    timer = setTimeout(() => fn.apply(this, args), delay);
  };
}

// Test case: search input
function fetchData(query) {
  console.log("Fetching data for:", query);
}

const debouncedFetch = debounce(fetchData, 1000);

// Simulating user typing
debouncedFetch("I");
debouncedFetch("In");
debouncedFetch("Inf");
debouncedFetch("Info");

Output

👉 Only last call executes after 1 second:

Fetching data for: Info

✅ Throttling

👉 Throttling ensures a function is executed at most once in a given interval.
Use case: Scroll event, window resize, drag events.

Example
// Throttle function
function throttle(fn, limit) {
  let lastCall = 0;
  return function(...args) {
    const now = Date.now();
    if (now - lastCall >= limit) {
      lastCall = now;
      fn.apply(this, args);
    }
  };
}

// Test case: scroll
function logScroll() {
  console.log("Scroll event fired at:", Date.now());
}

const throttledScroll = throttle(logScroll, 2000);

// Simulating multiple scroll calls
throttledScroll(); // Executes immediately
setTimeout(throttledScroll, 500);  // Ignored
setTimeout(throttledScroll, 2500); // Executes (after 2s)

Output

👉 Executes only once every 2 seconds, no matter how often triggered.

what is  Temporal Dead Zone (TDZ) ?

The Temporal Dead Zone (TDZ) is the period between when a variable is hoisted and when it is initialized in JavaScript.
During this time, if you try to access the variable, you’ll get a ReferenceError.
TDZ only applies to variables declared with let and const, not var.

5.Execution Context & Call Stack 

Execution Context is an environment where JavaScript executes code.

Whenever JavaScript runs your code, it creates an execution context to manage variables, functions and execution.

There are two important types:


Global Execution Context (GEC): The default environment where code outside any function runs.

Function Execution Context (FEC): A new context created every time a function is invoked.

Execution happens in two phases:

Creation Phase: JavaScript sets up memory. var variables are initialized with undefined (hoisting), function declarations are stored completely, and let/const enter the Temporal Dead Zone.

Execution Phase: Code is executed line by line, and actual values are assigned to variables.

The Call Stack is a LIFO (Last In, First Out) data structure that JavaScript uses to keep track of function execution. When a function is called, its context is pushed onto the stack, and when it finishes running, it is popped off the stack."
