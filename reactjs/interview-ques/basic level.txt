3.Functional vs Class Components?

“Functional components are simple JavaScript functions that use Hooks to manage state and lifecycle,
 while class components are ES6 classes with built-in lifecycle methods and this.state. 
 Functional components are preferred in modern React since they are easier to read, test, and optimize,
 while class components are considered legacy but still supported.”

4. What is the difference between state and props?
Props: Data passed from a parent to a child component. They are read-only and immutable.
meaning a child component cannot change the props it receives.

State: Data managed within a component. It is mutable and causes a component to re-render when it changes.

example:

// Parent component
function ParentComponent() {
  const userName = "Alice";
  return <ChildComponent name={userName} />;
}

// Child component
import React, { useState } from 'react';

function ChildComponent(props) {
  const [count, setCount] = useState(0);

  return (
    <div>
      <p>Hello, {props.name}!</p>
      <p>Button clicked {count} times.</p>
      <button onClick={() => setCount(count + 1)}>
        Click me
      </button>
    </div>
  );
}

6. Explain the Virtual DOM.

Answer: The Virtual DOM is a lightweight copy of the real DOM.When state or props change,
 React updates the Virtual DOM first, compares it with the previous version,
 and then updates only the necessary parts of the Real DOM. This makes UI updates faster and more efficient.

8.Controlled vs Uncontrolled components?

Controlled components are inputs managed by React state, giving full control, validation, and predictable behavior.
Uncontrolled components store values directly in the DOM and are simpler when you just need the value once, like on form submission.
In real projects, controlled components are preferred.

 Example:

 Example (Controlled Input):

 import { useState } from "react";

function ControlledInput() {
  const [name, setName] = useState("");

  return (
    <div>
      <input 
        type="text" 
        value={name}   // React controls the value
        onChange={(e) => setName(e.target.value)} 
      />
      <p>Your name: {name}</p>
    </div>
  );
}


Example (Uncontrolled Input):

import { useRef } from "react";

function UncontrolledInput() {
  const inputRef = useRef();

  const handleSubmit = () => {
    alert("Your name: " + inputRef.current.value);
  };

  return (
    <div>
      <input type="text" ref={inputRef} />  {/* DOM stores the value */}
      <button onClick={handleSubmit}>Submit</button>
    </div>
  );
}

12.what is useeffect?

useEffect is a React Hook used to perform side effects in functional components.
A side effect is any action that affects something outside the component, such as:

Fetching data from an API

Updating the DOM manually

Setting up subscriptions or timers

Logging values


Example: Fetching Data

import React, { useState, useEffect } from 'react';

function DataFetcher() {
  const [data, setData] = useState(null);

  // This effect runs once when the component mounts
  useEffect(() => {
    fetch('https://api.example.com/data')
      .then(response => response.json())
      .then(result => setData(result));
  }, []); // The empty dependency array ensures this effect runs only once

  return <div>{data ? <p>Data loaded!</p> : <p>Loading...</p>}</div>;
}

13. what is useContext ?

useContext is a React Hook that allows you to access data from a context directly,
 without having to pass props manually through every level of the component tree (a problem called prop drilling).

It is commonly used for global state management like authentication, themes, or user settings.

Syntax:
const value = useContext(MyContext);


MyContext → the context you created with React.createContext()

value → the data provided by the nearest Context.Provider

Example: Theme Context
import React, { createContext, useContext } from "react";

// 1. Create a context
const ThemeContext = createContext("light");

function ThemedButton() {
  // 2. Use useContext to consume value
  const theme = useContext(ThemeContext);
  return <button>{`Theme is ${theme}`}</button>;
}

function App() {
  return (
    // 3. Provide context value
    <ThemeContext.Provider value="dark">
      <ThemedButton />
    </ThemeContext.Provider>
  );
}

export default App;

14.what is useRef ?

useRef is a React Hook that gives you a way to persist values across renders without causing a re-render.
It is mainly used for two things:

Accessing/manipulating DOM elements directly

Storing mutable values (like timers, counters, previous values) that don’t trigger re-renders when changed.

Syntax:
const ref = useRef(initialValue);


ref.current → stores the mutable value or DOM element reference.

The value in ref.current persists across renders, but updating it does not trigger a re-render.

import React, { useRef } from "react";

function InputFocus() {
  const inputRef = useRef(null);

  const focusInput = () => {
    inputRef.current.focus(); // directly focus DOM element
  };

  return (
    <div>
      <input ref={inputRef} type="text" placeholder="Type here..." />
      <button onClick={focusInput}>Focus Input</button>
    </div>
  );
}

export default InputFocus;

15.what is useMemo ?

useMemo is a React Hook that memoizes (caches) the result of an expensive calculation so that it only recomputes when its dependencies change.

It helps in performance optimization by preventing unnecessary recalculations on every render.

import React, { useState, useMemo } from "react";

function ExpensiveCalculation() {
  const [count, setCount] = useState(0);
  const [input, setInput] = useState("");

  // Expensive function (e.g., looping a million times)
  const slowCalculation = (num) => {
    console.log("Calculating...");
    for (let i = 0; i < 1000000000; i++) {}
    return num * 2;
  };

  // useMemo caches the result until 'count' changes
  const doubled = useMemo(() => slowCalculation(count), [count]);

  return (
    <div>
      <h3>Doubled Value: {doubled}</h3>
      <button onClick={() => setCount(count + 1)}>Increment</button>
      <input
        type="text"
        value={input}
        onChange={(e) => setInput(e.target.value)}
        placeholder="Type something"
      />
    </div>
  );
}

export default ExpensiveCalculation;

 16.what is use useReducer ?

 useReducer is a React Hook used for state management in functional components.
It’s an alternative to useState, and is particularly useful when:

1.The state is complex (multiple sub-values).

2.The next state depends on the previous state.

3.You want a more structured way to manage state updates (like Redux).


import React, { useReducer } from "react";

// Reducer function
function reducer(state, action) {
  switch (action.type) {
    case "increment":
      return { count: state.count + 1 };
    case "decrement":
      return { count: state.count - 1 };
    case "reset":
      return { count: 0 };
    default:
      return state;
  }
}

function Counter() {
  const [state, dispatch] = useReducer(reducer, { count: 0 });

  return (
    <div>
      <h3>Count: {state.count}</h3>
      <button onClick={() => dispatch({ type: "increment" })}>+</button>
      <button onClick={() => dispatch({ type: "decrement" })}>-</button>
      <button onClick={() => dispatch({ type: "reset" })}>Reset</button>
    </div>
  );
}

export default Counter;

17.what is useCallback ?

useCallback is a React Hook that memoizes a function, so it only re-creates that function when its dependencies change.

It helps in performance optimization, especially when passing functions as props to child components — preventing unnecessary re-renders.


import React, { useState, useCallback } from "react";

function Child({ onClick }) {
  console.log("Child rendered");
  return <button onClick={onClick}>Click Me</button>;
}

function Parent() {
  const [count, setCount] = useState(0);

  // Without useCallback → new function created every render
  // const handleClick = () => console.log("Clicked!");

  // With useCallback → function is memoized
  const handleClick = useCallback(() => {
    console.log("Clicked!");
  }, []);

  return (
    <div>
      <h3>Count: {count}</h3>
      <button onClick={() => setCount(count + 1)}>Increment</button>
      <Child onClick={handleClick} />
    </div>
  );
}

export default Parent;

18. what is useLayoutEffect ?

useLayoutEffect is similar to useEffect, but it runs synchronously after the DOM updates, and before the browser paints the screen.

This means:

1.useEffect → runs asynchronously after painting (user may see changes happen later).

2.useLayoutEffect → runs synchronously before painting (user sees updates instantly).

It is useful when you need to measure DOM elements or synchronously apply changes before the user sees the UI.

import React, { useState, useRef, useLayoutEffect } from "react";

function Box() {
  const [width, setWidth] = useState(0);
  const boxRef = useRef(null);

  useLayoutEffect(() => {
    // Runs before the browser paints
    setWidth(boxRef.current.offsetWidth);
  }, []);

  return (
    <div>
      <div ref={boxRef} style={{ width: "200px", height: "100px", background: "skyblue" }}>
        Box
      </div>
      <p>Box width: {width}px</p>
    </div>
  );
}

export default Box;

19. What is the Diffing Algorithm in React?

The Diffing Algorithm is how React finds the differences between the old Virtual DOM and the new Virtual DOM.

1.If element types differ → React replaces the old node.

2.If types are the same → React updates only the changed props.

3.For lists → React uses keys to identify which items changed, moved, or stayed the same.

This approach reduces unnecessary re-renders.


--------------------------------------------------------------------------------------------------------------
20.What is Reconciliation in React?

Reconciliation is the overall process of updating the Real DOM.

1.React renders a new Virtual DOM.

2.It uses the Diffing Algorithm to find differences from the old Virtual DOM.

3.Then React applies only those minimal changes to the Real DOM.

In short: Reconciliation = Virtual DOM + Diffing + Real DOM updates.

------------------------------------------------------------------------------------------------------------------

21.React uses the Virtual DOM to avoid direct heavy operations on the Real DOM. 
It compares old and new Virtual DOM trees using the Diffing Algorithm,
 and through Reconciliation, it efficiently updates only the changed parts of the Real DOM

 31.What is Debounce?

Definition:

Debounce is a technique to limit how often a function is executed.

In React, it’s often used for search inputs, so the function runs only after the user stops typing for a certain time.

Use case:

Search bars

API calls while typing

Resize or scroll events


import React, { useState, useEffect } from "react";

function DebouncedSearch() {
  const [query, setQuery] = useState("");
  const [debouncedQuery, setDebouncedQuery] = useState("");

  useEffect(() => {
    // Set a timer
    const timer = setTimeout(() => {
      setDebouncedQuery(query);
    }, 500); // 500ms delay

    // Clear previous timer if query changes
    return () => clearTimeout(timer);
  }, [query]);

  return (
    <div>
      <h2>Debounced Search</h2>
      <input
        type="text"
        value={query}
        onChange={(e) => setQuery(e.target.value)}
        placeholder="Type here..."
      />
      <p>Search Query: {debouncedQuery}</p>
    </div>
  );
}

export default DebouncedSearch;

3.Todo List (Add, Display, Delete)

import React, { useState } from "react";

function TodoApp() {
  const [task, setTask] = useState("");
  const [todos, setTodos] = useState([]);

  const addTask = () => {
    if (task.trim() === "") return;
    setTodos([...todos, task]);
    setTask("");
  };

  const deleteTask = (index) => {
    setTodos(todos.filter((_, i) => i !== index));
  };

  return (
    <div>
      <h2>Todo List</h2>
      <input
        type="text"
        value={task}
        onChange={(e) => setTask(e.target.value)}
        placeholder="Enter task"
      />
      <button onClick={addTask}>Add</button>

      <ul>
        {todos.map((t, index) => (
          <li key={index}>
            {t} <button onClick={() => deleteTask(index)}>❌</button>
          </li>
        ))}
      </ul>
    </div>
  );
}

export default TodoApp;

1.Difference between map(), forEach(), and filter()?

1.map() → Returns a new array with transformed elements.

2.forEach() → Loops through elements, does not return a new array.

3.filter() → Returns a new array with elements that satisfy a condition.

let arr = [1, 2, 3, 4];
console.log(arr.map(x => x * 2));   // [2, 4, 6, 8]
arr.forEach(x => console.log(x));   // prints 1,2,3,4
console.log(arr.filter(x => x > 2)); // [3,4]
